# Skill library audit — harvest of 2026-09-21

Branch `skill-harvest-2026-09`. Nothing was deleted; every removal below is a recommendation.

## Summary

- Library: **646 skills** (382 before, **264 added**, 0 removed).
- Sources: 75 upstream repositories, every added skill carries a `SOURCE.json` (repo, commit, path, license) folded into [SOURCES.md](SOURCES.md).
- Dedupe: 61 clusters graded by running every contender on one shared task; 48 clusters have a single winner, 13 were judged to hold genuinely different jobs.
- Purge recommendation: **50 lines** — 49 individual skills plus the 260-skill plugin-duplication decision (see the last section).
- Provenance backfilled for the whole library: 645 of 646 skills now carry `SOURCE.json`. 340 pre-existing skills were byte-matched to `alirezarezvani/claude-skills@aa8d778`, 31 to `mattpocock/skills` commits, 2 to `google-gemma/gemma-skills`, 1 each to `danyuchn/asd-ste100-skill` and `agenvoy/skill-readme-generate`; 4 (`grill-me`, `pw`, `md-document`, `sample-skill`) exist upstream but match no upstream commit, so their row is marked `local_divergence`. The one without a row, `svg-to-pdf`, is authored in this repo.
- Two load-breaking frontmatter bugs in pre-existing skills were fixed (`design-system`, `md-slides`: unquoted `: ` in the description made the YAML invalid); `litreview`'s description was trimmed under the 1024-character cap. Every edit is recorded under `patches` in the skill's `SOURCE.json`.
- Structural finding: **260 library skills are also installed on this machine as the seven `claude-code-skills` plugins** (`engineering-advanced-skills` 78, `c-level-skills` 62, `engineering-skills` 51, `marketing-skills` 48, `pm-skills` 9, `business-operations-skills` 7, `business-growth-skills` 5). Claude Code loads both copies every session. Recommendation: uninstall those seven plugins (`claude plugin uninstall <name>@claude-code-skills`) and drop them from `plugins.lock.json`; the library copies are pinned and provenance-tracked. The alternative — purging the 260 from the library — is listed in the purge section as one line, not 260.
- Second structural finding: the authoring machine also has the `masterskills` plugin itself installed (`~/.claude/plugins/cache/masterskills/masterskills/1.1.0`, 382 skills) **and** the `~/.claude/skills` mirror of the same 382 — so every library skill is loaded twice locally, and the 260 above three times. Keep one loading path on this machine: either the mirror (authoring) or the plugin, not both.
- Context cost, for the owner's judgment: skill names plus descriptions now total ≈69k tokens per session (was ≈37k for 382). That is the real price of a 646-skill library and the reason the harvest stopped at 264 rather than the ~900 candidates the scouts graded A/B.

## Method

1. **Discovery** — four parallel scouts: official vendor repos (36 repos, ~1,800 SKILL.md folders), curated awesome-lists (16 lists, 1,089 linked repos, ~70 evaluated in depth), GitHub topic/code search (267 repos, 81 tree-scanned), and web directories (skills.sh leaderboard, ~277 skills across ~60 repos). Each scout fetched every candidate SKILL.md, checked frontmatter, referenced files, license and injection patterns, and compared the job against the existing index. Combined: ~1,300 candidate rows, 892 graded A or B.
2. **Selection** — A-grade first; B only to fill a gap the library lacked (Java, Flutter, .NET, Swift, Go, game dev, LinkedIn, scientific writing, n8n, fine-tuning). Vendor-specific skills only for mainstream stacks (Vercel, Supabase, Cloudflare, Stripe, Expo, PostHog, Sentry, Prisma, Neon, MongoDB, Resend, Upstash, Pulumi, Terraform, AWS serverless, GCP basics, Grafana/k6/PromQL, HF, OpenAI, ElevenLabs). Skipped whole product suites (Datadog 46, Google 129, Microsoft 60, Grafana internals), MCP-omnibus wrappers, unlicensed or GPL/AGPL/CC-NC repos, offensive-security playbooks, and anything whose only input comes from a sibling skill or a plugin runtime.
3. **Vendoring** — new `scripts/vendor_skill.py`: shallow sparse clone, verbatim copy, nested `.git` stripped, repo `LICENSE` copied in when the skill has none, `SOURCE.json` written with repo/ref/commit/path/license/date. 306 skills vendored in three batches.
4. **Vetting** — `skill-security-auditor` over every vendored skill (241 PASS / 20 WARN / 27 FAIL), then four reviewer agents read every SKILL.md and every flagged file: all 27 FAILs were false positives (security tutorials describing attacks, official installers, `subprocess` with list args, test fixtures); 0 real security risks; 9 skills dropped for being unable to work standalone or too thin.
5. **Lint** — new `scripts/check_skills.py`: PyYAML frontmatter parse, name/directory match, 1024-char description cap, every relative reference resolves, `SOURCE.json` valid and (with `--network`) the commit and path still exist on GitHub. Dangling sibling links in vendored skills were rewritten to pinned upstream URLs (recorded as patches); 3 over-long descriptions trimmed.
6. **Dedupe by running** — 61 clusters, 165 contender runs, 61 blind judges, as one deterministic Workflow. Every contender in a cluster was executed by an identical fresh Sonnet runner on the same realistic task (a fixture Flask repo with eight planted defects for the review/security/debug clusters; numeric business scenarios elsewhere). Runners logged files read, missing files and every guess. An Opus judge scored the transcripts and deliverables blind (labels A-H, skill names hidden) on one rubric. 13 newly vendored skills that lost their cluster at ≤6/10 were not added.
7. **Verification** — three passes over the final tree (details at the end).
